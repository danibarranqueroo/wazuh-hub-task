The lab at a glance

  • Server side is the official wazuh-docker single-node compose on Docker Desktop.
  • The agent is a real Ubuntu VM in OrbStack; it reaches the manager through host.orb.internal.
  • Ports as published: 1514/1515 tcp, 514 udp and 55000 on the manager, 9200 indexer, 443 to 5601 dashboard.
  • Version 4.14.9: latest stable 4.x tag on wazuh-docker when I started; images have arm64 builds.

Why this setup

Server stack

Docker, official compose

  • The Wazuh OVA is x86-only
  • This Mac is Apple Silicon
  • Reproducible, quick to tear down
Agent host

OrbStack Ubuntu VM

  • A real host: systemd, SSH, a filesystem
  • Detections behave like production
  • Known from Falco proofs of concept at Prowler
  • OVA would not run on Apple Silicon, so Docker was the obvious route; the 4.14.9 images have arm64 builds.
  • I wanted a real Linux host for the agent so SSH brute force and FIM behave as they would on a server.
  • OrbStack: at Prowler we used it for Falco PoCs, since Falco only runs on Linux.

How an event travels

SSH log line → rule 5710 → alert → Threat Hunting

File change → rule 550 → alert → FIM events

  • Agent daemons collect: logcollector reads logs, syscheckd watches files. Events go to remoted on 1514.
  • analysisd decodes and matches rules; a match above the threshold becomes an alert.
  • Filebeat inside the manager container ships alerts to the indexer; the dashboard queries the indexer.
  • Kept at the level checked in docs/architecture.md: daemons verified running, Filebeat output host verified.

Phase 2 · Agent Hardening Brief

“I have hundreds of failed CIS checks.
What do I fix first?”

Long lists

Deciding what comes first is the hard part

Read-only

Current state from the server API

Honest

Says what it could not check

  • A real question for whoever runs Wazuh: SCA gives a long list, not an order.
  • Output: top five fixes, why, remediation, evidence, and a coverage note.
  • Small on purpose: one endpoint, one page, server API only (ADR 0001).

Architecture

  • One FastAPI process. posture.py collects and computes coverage gaps by rule; wazuh_client.py is read-only with JWT cache, retries and typed errors.
  • LLM_PROVIDER picks the summarizer. auto: Claude API if a key is set, else mock. claude-code is opt-in only.
  • Any model failure falls back to the mock on the same input; the response says which one ran.

What one brief contains

summarythe situation, two sentences
fixestop 5: why, fix, evidence
coverageconfidence, counts, gaps
sourceclaude · claude-code · mock
fallback_reasonwhy the mock ran
stalecached copy, Wazuh down

Failure handling

FailureBehaviour
Wazuh slow or flakyTimeout, retries with backoff on errors, 429, 5xx
Wazuh downCached brief with stale: true, else 503
Wazuh auth fails502 wazuh_auth_failed, never hidden by cache
Model down or bad outputMock writes it; fallback_reason says why
Is it us or Wazuh?/healthz process · /readyz Wazuh call

Every path has tests; none needs the lab or a key. Runbook: docs/runbook.md.

  • A JWT is cached until shortly before expiry, and a 401 triggers one fresh login.
  • Auth failures are deliberately not masked by the stale cache: a credentials problem must be visible.
  • Future: circuit breaker, queue and workers, shared cache so a restart keeps stale copies.
